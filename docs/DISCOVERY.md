# RSS и поисковые метаданные

В многоредакционном preview каждой аудитории соответствует собственный RSS по
её базовому маршруту. Canonical/hreflang сохраняют аудиторию; sitemap проверяется
для всех выбранных редакций вместе. Прежние инженерные URL и GUID не меняются.
См. [READERS.md](READERS.md).

Основной адрес по выбору владельца: `https://repravda.com`. Сборщик использует его
в RSS, canonical, hreflang и sitemap. Это настройка адресов, не публикация сайта.

## Результат сборки

- `/ru/rss.xml`, `/en/rss.xml`, `/ja/rss.xml`: RSS 2.0 с заголовком, аннотацией,
  языком, категорией и ссылкой на каждую статью. Сначала идут новые выпуски.
- На веб-страницах есть обнаруживаемая браузером ссылка на RSS в `<head>` и
  видимая ссылка в футере. Локальная ссылка в футере открывает локальный XML;
  адреса записей внутри него используют основной адрес сайта.
- `<link rel="canonical">` указывает постоянный адрес страницы. Корень `/`
  ссылается на `/ru/`; совместимые адреса `/ru/articles/<slug>/` — на статью
  с датой выпуска. Главная, архив и датированная страница номера имеют свои адреса.
- `<link rel="alternate" hreflang="ru|en|ja">` связывает соответствующие страницы
  всех трёх языков, включая текущий язык. Статьи сопоставляются по `article.id`,
  поэтому разные переведённые slug допустимы. Печатный HTML ссылается на страницу
  своего номера. У статей также есть отдельные title и meta description.
- `/sitemap.xml` перечисляет подходящие главные, архивы, номера и полные статьи.
  Дублирующие адреса, печатные HTML, PDF, служебные JSON и картинки туда не входят.

## Готовность номера и публикация

По порядку, установленному владельцем 31 октября, успешная генерация или импорт
полного выпуска сразу присваивает ему `approved`. Это техническая готовность
материала к локальной сборке и включению в RSS/sitemap. Отдельно менять статус
после каждого выпуска не требуется. Окончательный просмотр и подтверждение
размещения выполняются во время загрузки в Cloudflare; детали задаст адаптер
публикации. Сам по себе `approved` не является разрешением на загрузку.

RSS и sitemap включают номера со статусом `approved` или `published`.
Явно сохранённые незавершённые `draft`/`review` остаются исключены из списков:
сборщик не переводит произвольные рабочие файлы в готовые номера. Если главный
номер ещё draft, его главные исключаются из sitemap; если в выбранной истории
есть draft/review, исключается и страница списка архива. Готовые отдельные номера
при этом остаются в RSS/sitemap.

Текущие выпуски за 30 и 31 октября в `content/technical/` имеют `approved`;
в сборке `previews/archive-2026-10-31-8` есть записи RSS и карта сайта.
Исторические сборки и демонстрационный вымышленный номер не изменены.
Если подходящих страниц нет, RSS остаётся без записей, а `sitemap.xml` не создаётся.

Обычный build остаётся preview-only: `noindex,nofollow` и `Disallow: /` сохранены.
Явный `--publication` готовит читательские страницы с разрешённой индексацией;
`rp release` экспортирует их для GitHub/Cloudflare. Эти команды ничего не
загружают. См. [DEPLOYMENT.md](DEPLOYMENT.md). При наличии sitemap в robots.txt
добавляется его полный адрес.

## Устойчивость RSS и даты

GUID имеет вид `replicantpravda:<date>:<lang>:<article.id>` с `isPermaLink=false`.
Редакция, заголовок, slug или адрес хостинга могут измениться без изменения GUID;
переводы и номера с разными датами имеют разные идентификаторы. Глоссарий остаётся
доступен на сайте и в sitemap, но отдельной новостью в RSS не становится.

RSS-аннотация берётся из `dek` или первого абзаца `body`; текст экранируется как
буквальный текст, включая потенциальный HTML. `pubDate` — дата выпуска в 00:00
JST, техническое представление известной даты, а не фактическое время размещения.
Время сборки не используется. `lastmod` в sitemap не выдумывается: поле реального
времени исправления пока отсутствует в редакционной модели.

## Команды

```sh
rp build --issue 2026-10-31 --content-dir content/technical \
  --archive-issue content/technical/2026-10-30.json \
  --site-url https://repravda.com --pdf --output previews/archive-2026-10-31-8
rp verify --issue 2026-10-31 --output previews/archive-2026-10-31-8
rp preview --output previews/archive-2026-10-31-8
```

`--site-url` необязателен: по умолчанию используется `https://repravda.com`.
Для проверки адресов полностью локально можно передать `http://127.0.0.1:8000`.
Допускается только HTTP(S)-адрес без пути, учётных данных, параметров и fragment.
Сеть для сборки не нужна. Существующие каталоги не перезаписываются.

`site.json` сохраняет основной адрес и наличие sitemap; файлы входят в контрольные
суммы снимка. Сборка и `rp verify` проверяют внутренние адреса метаданных, взаимность
hreflang, XML, состав RSS/GUID и соответствие карты сайта допустимым страницам.

## Источники форматов

- [RSS 2.0 specification](https://www.rssboard.org/rss-specification).
- [Google: localized versions](https://developers.google.com/search/docs/specialty/international/localized-versions).
- [Sitemaps XML protocol](https://www.sitemaps.org/protocol.html).

Страница о газете по маршруту about/ сохраняет языковую и читательскую редакцию, имеет canonical/hreflang и включается в sitemap при готовом текущем выпуске. Для инженерного сайта упаковщик допускает about/index.html. Многоредакционная публикация остаётся отдельной будущей настройкой; текущий просмотр локальный.
