## Что делает задача

1. Блокирует параллельный запуск и получает актуальные `main` и `develop`.
2. Создаёт отдельный рабочий каталог от `origin/main`; берёт из `develop` только
   `data/`. Код будущей разработки автоматически не публикуется.
3. Проверяет все 12 feed: четыре редакции × RU/EN/JA. Требуется дата сегодняшнего
   дня в Токио. Если новых данных нет или они ещё вчерашние, push не выполняется.
4. Сохраняет номер/историю из нормализованных опубликованных источников. Для новой
   даты номер увеличивается на один; исправление уже опубликованного номера
   получает следующую ревизию. Получает погоду трёх городов для новой даты.
5. Строит сайт, архив и PDF, растеризует страницы и проверяет текст, шрифты,
   наложения, ссылки, metadata и контрольные суммы. Экспортирует только читательские
   файлы. Словари и японские чтения сохраняются; картинки `null` не дают пустых рамок.
6. Только после проверки создаёт коммит с `data/`, `content/editions/`,
   `content/weather/`, `public/`, `public.release.json` и выполняет обычный push
   `HEAD:main`. Force-push не используется; конкурентное изменение main остановит push.
7. Cloudflare проверяет и публикует этот комплект. Telegram workflow проверяет
   успех Cloudflare и реальные страницу/PDF перед единственной попыткой отправки.

При любой ошибке сборки коммит и push не выполняются. Ошибка деплоя сохраняет
предыдущую рабочую публикацию Cloudflare. Подготовленные источники, снимки, PDF и
коммиты остаются в отдельных каталогах запуска; рабочая папка в Documents и её
незакоммиченные правки не используются. Автоматизация не вызывает ИИ/API модели.

## Установка

```sh
.venv/bin/python scripts/install_daily_publish.py
```

Скрипт устанавливает отдельный clone `main` и venv в
`~/Library/Application Support/ReplicantPravda/`. Пакеты закреплены в pyproject,
Chromium закреплён версией Playwright. `gh` должен быть авторизован владельцем;
пароли и токены в plist не записываются. Токен Telegram остаётся в GitHub Environment.

LaunchAgent:
`~/Library/LaunchAgents/com.repravda.daily-publish.plist`.
StartCalendarInterval: Hour 6, Minute 20; RunAtLoad выключен. Расписание использует
системный часовой пояс Mac — при установке это JST. `TZ=Asia/Tokyo` фиксирует
дату выпуска внутри процесса; при изменении системного пояса расписание тоже
потребует пересмотра. Запуск выполняется в пользовательской сессии. Mac должен
быть включён, пользователь — войти в систему. Пропущенное во сне календарное
событие выполняется после пробуждения; выключенный Mac не просыпается от этой
задачи. `caffeinate -i` удерживает Mac от автоматического простоя во время сборки.

Поведение расписания: [Apple launchd documentation](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html).

## Проверка, ручной запуск и остановка

```sh
launchctl print gui/$(id -u)/com.repravda.daily-publish

# Настоящий запуск с публикацией по уже выданному разрешению:
launchctl kickstart gui/$(id -u)/com.repravda.daily-publish

# Отключение до следующей установки/входа:
launchctl bootout gui/$(id -u)/com.repravda.daily-publish
```

Для постоянного отключения после bootout переместите plist из LaunchAgents.
Журналы: `~/Library/Application Support/ReplicantPravda/logs/daily.log` и
`daily-error.log`. Итог последней публикации — `last-run.json`; полные результаты —
`runs/<timestamp>/result.json`, снимок в `snapshot/`, подготовленный релиз в `public/`.
Каталоги запусков сохраняются для восстановления и могут занимать место; старые
можно удалить вручную после проверки успешных публикаций.

Для ручной подготовки без push запускайте `scripts/daily_publish.py --state PATH`
отдельным Python этой установки. `--push` явно включает публикацию, `--force`
повторяет подготовку при неизменных данных. Если push не состоялся, сначала
просмотрите сохранённый коммит и состояние main: автоматический force-push не
предусмотрен. Если деплой не удался, проверьте Cloudflare; подготовленные материалы
не пропадают. Для восстановления анонса сначала проверьте канал, затем следуйте
[TELEGRAM.md](TELEGRAM.md), чтобы не получить дубликат.
