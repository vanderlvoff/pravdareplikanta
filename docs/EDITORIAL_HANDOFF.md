# Перенос материалов из ChatGPT в выпуск

Редакционный результат передаём отдельным файлом JSON. Сборщик газеты не читает
историю чатов и не обращается к модели. Для текущего этапа API не требуется.
Можно также передать выбранные тексты в Markdown: затем их нужно оформить в JSON.

## Если материалы уже готовы в другом чате

В исходном чате попросите собрать только окончательные редакционные версии, без
переписки о дизайне, инструкций и отклонённых вариантов. Сохраните результат в файл
UTF-8. Не превращайте отсутствие материала или источника в выдуманный факт.

Для точного формата приложите к тому чату `content/issue.schema.json` и текущий
`content/issues/2026-10-29.json` как пример структуры. Тексты статей этого примера
вымышлены, ссылки example.org — заглушки, их нельзя переносить в настоящий выпуск.
Манифест изображений, сами изображения и вёрстка в редакционный JSON не включаются.

Готовый запрос для чата:

> Собери редакционные материалы из этой беседы в один JSON-файл UTF-8 для газеты
> «Правда репликанта». Используй приложенную JSON Schema и структуру примера.
> Возьми только окончательные согласованные тексты; не включай нашу переписку,
> команды, обсуждение макета и отклонённые варианты. Не сокращай согласованный текст
> молча. Не используй демонстрационные статьи и заглушки источников из примера.
>
> Сохрани согласованные дату, номер и revision выпуска; для полностью сформированного выпуска status установи approved; окончательное подтверждение публикации выполняется при загрузке в Cloudflare.
> Подготовь ru/en/ja с одинаковыми article.id во всех языках и стабильными slug.
> Для статьи укажи category, headline, dek, body, sources ; print_page можно опустить: страницы распределяет сборщик.
> Допустимые блоки body: paragraph, heading, quote, caption с text; list с items.
> HTML и изображения в body не используй. Для источника нужны реальный URL,
> заголовок и дата публикации; дата получения — если известна.
>
> Не придумывай факты, ссылки, даты, цитаты и отсутствующие переводы. Если чего-то
> не хватает, сначала перечисли пробелы отдельным сообщением; не выдавай такой
> выпуск за законченный. Новые переводы подготовь для отдельной редакционной
> проверки. Различай news, analysis, opinion и satire.
>
> Погоду не сочиняй: исключи поле weather, мы подключим сохранённый снимок отдельно,
> либо сохрани уже проверенный объект weather, только если его дата совпадает
> с датой выпуска. Объём проверит наш локальный PDF-сборщик; не обещай заранее,
> фиксированное число страниц.
>
> Когда обязательные данные готовы, создай скачиваемый JSON-файл без комментариев
> и Markdown-ограждений внутри файла. Если создание файла недоступно, выведи
> чистый JSON в одном блоке кода.

## Локальная проверка

Сначала сохраните полученный файл отдельно от существующего выпуска, например в
`previews/editorial-import.json`, и выполните:

```sh
rp validate previews/editorial-import.json
```

Техническая валидация не подтверждает достоверность новостей, качество перевода
или пригодность источников. Сформированный полный выпуск со статусом approved перенесите в
`content/issues/<issue_id>.json`. Не перезаписывайте существующий источник молча:
правки ранее опубликованного выпуска требуют новой revision.

Для issue_id 2026-10-29:

```sh
rp build --issue 2026-10-29 --pdf --output previews/editorial-review
rp verify --issue 2026-10-29 --output previews/editorial-review
rp preview --output previews/editorial-review
```

Для другой даты замените issue_id в командах. Проверьте все девять PNG-страниц.
При переполнении отчёт `<output>.failed.json` укажет материалы для сокращения или
переноса на другую страницу. Публикация остаётся отдельным последующим этапом.

JSON Schema можно обновить из действующих моделей:

```sh
python scripts/export_schema.py
```

Передача готовых файлов соответствует [официальной инструкции OpenAI о работе с файлами](https://learn.chatgpt.com/docs/artifacts-viewer).
