# Анонсы номера в Telegram

Канал владельца: [@pravdareplicanta](https://t.me/pravdareplicanta).
Формат: один короткий русский пост на номер, одна постоянная ссылка на русский
инженерный выпуск. Вступление берётся из редакционной заметки номера; отдельный
запрос к ИИ не нужен. Переводы и отдельные посты для остальных редакций не отправляются.

Владелец разрешил подключение к production и проверку настоящего анонса 1 ноября
2026. Расписание публикации с Mac описано в [DAILY_PUBLICATION.md](DAILY_PUBLICATION.md).
Обычная локальная сборка ничего не отправляет.

## Предпросмотр без бота

```sh
.venv/bin/rp telegram --issue previews/readers-2026-11-01-2/source.json
```

`--issue` принимает внутренний нормализованный JSON после импорта/сборки, а не
сырой файл `data/latest/engineer/ru.json`. Выпуск должен иметь статус
`approved` или `published`. Команда только печатает текст и отметку PREVIEW ONLY.
Можно сохранить пакет через `--output previews/telegram-next.json`; существующий
файл не перезаписывается. Токен и сеть для предпросмотра не нужны.

## Подключение бота

1. Откройте официальный [@BotFather](https://t.me/BotFather), отправьте `/newbot`
   и задайте имя и username бота. Полученный токен не присылайте в чат и не
   добавляйте в файлы проекта.
2. Добавьте созданного бота в администраторы канала `@pravdareplicanta` с правом
   публикации сообщений. Остальные административные права для анонсов не нужны.
3. Владелец сохранил секрет в GitHub Environment `TELEGRAM_BOT_TOKEN`.
   Workflow подключён к этому окружению. Путь для обновления токена:
   **Settings → Environments → TELEGRAM_BOT_TOKEN → Environment secrets**.
   Имя секрета: `TELEGRAM_BOT_TOKEN`, значение: токен от BotFather.
   Дублировать его в Repository secrets не нужно. GitHub выдаёт временный
   `GITHUB_TOKEN` самостоятельно. Если у окружения включены правила допуска
   веток или ручное подтверждение, они применяются и к этому заданию.
4. После отдельного просмотра и разрешённой публикации изменений workflow должен
   находиться в `main`, а новый проверенный комплект `public/` должен включать
   `announcement.json` и соответствующий `public.release.json`. Старый комплект
   без этих метаданных продолжает работать как сайт, но не подходит для отправки.
5. В **Actions → Telegram issue announcement → Run workflow** выберите `main` и
   оставьте **Preview without sending** включённым. В журнале будет текст без
   отправки. Для этого шага токен и включение автоматизации не требуются.
   Чтобы отдельно проверить токен и права бота без сообщения и ожидания деплоя,
   включите **Only verify bot credentials and channel posting rights**. Проверка
   вызывает только getMe/getChatMember; данные аккаунта и токен в журнал не выводятся.
6. Когда всё готово, в **Settings → Secrets and variables → Actions → Variables →
   New repository variable** задайте `TELEGRAM_ANNOUNCEMENTS_ENABLED` = `true`.
   Следующий разрешённый push в `main` запустит проверку и отправку. Чтобы
   анонсировать уже опубликованный свежий номер, запустите workflow из `main`
   вручную, сняв **Preview without sending**: это настоящая публикация в канале.

Создание бота: [официальная инструкция Telegram](https://core.telegram.org/bots/features#creating-a-new-bot).
Параметры канала, права и формат запроса: [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage).

## Когда отправляется пост

Workflow запускается после push в `main`, читает код из `main` и ждёт успешную
проверку `Workers Builds: pravdareplikanta` от приложения Cloudflare
`cloudflare-workers-and-pages` (app ID 85455). Название приложения/проверки
закреплено в `scripts/telegram_announce.py`; при переименовании Worker его нужно
обновить явно. Другие ветки, форки и устаревшие коммиты не дают права отправки.

После подтверждения Cloudflare проверяются реальные файлы на `https://repravda.com`:
метаданные анонса, страница русского номера и его PDF. Их SHA-256 должны совпасть
с просмотренным релизом. Ошибка деплоя, недоступные файлы или несовпадение
останавливают отправку. Автоматическое окно — дата номера от сегодня до 14 дней
назад включительно, по часовому поясу Asia/Tokyo; будущие и более старые номера
не анонсируются.

`rp release` добавляет публичный `announcement.json`: только дату, номер, ревизию,
статус, язык, вступление, ссылку и готовый текст. Это не исходный редакторский JSON.
Пакет покрывается контрольными суммами релиза. Токен существует только в секрете
GitHub Actions; Cloudflare, браузер читателя и локальный предпросмотр его не получают.

## Повторы и восстановление

Перед единственной попыткой отправки workflow сохраняет артефакт
`telegram-issue-YYYY-MM-DD` с датой номера, коммитом и отметкой reserved. Токена и
данных аккаунта в нём нет. Срок хранения — 90 дней; автоматическое окно отправки
короче срока хранения. Все запуски сериализованы. Наличие артефакта блокирует
повтор, включая новую ревизию того же номера и обновление оформления сайта.

Если Telegram не подтвердил результат или запуск оборвался после резервирования,
автоматического повторного запроса нет. Сначала проверьте сам канал: сообщение
могло дойти даже при сетевой ошибке. Если пост уже есть, ничего повторять не нужно.
Если поста точно нет, исправьте причину и только затем удалите артефакт именно
этого номера в соответствующем запуске Actions и запустите workflow вручную из
`main` со снятым предпросмотром. Удаление всего запуска также удаляет его артефакты.
Это защита от слепых повторов, а не гарантия exactly-once со стороны Telegram.

Для отключения достаточно удалить `TELEGRAM_ANNOUNCEMENTS_ENABLED` либо задать
`false`. При компрометации токена перевыпустите его через BotFather и замените
секрет GitHub. HTTP-адрес Bot API содержит токен, поэтому код не выводит адреса
запросов, тела ошибок Telegram или сырые исключения в журнал.

GitHub: [workflow events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows),
[artifacts API](https://docs.github.com/en/rest/actions/artifacts).
