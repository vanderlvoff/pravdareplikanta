# Черновик выпуска через OpenAI API

По запросу владельца добавлена отдельная команда `rp draft`. Она получает новый
редакционный материал через Responses API; историю пользовательских чатов она не
импортирует. Локальные `validate`, `build`, `verify`, `preview` по-прежнему работают
без API. Новых Python-зависимостей для API-команды нет.

## Подключение

Нужны API-ключ, доступная вашему API-проекту модель с поддержкой web search и
Structured Outputs, а также настроенный доступ к платному API. Модель задаётся
явно через `--model` или `OPENAI_MODEL`; скрытого выбора модели нет.

Ключ передавайте только локально в переменной окружения. Для терминала zsh:

```sh
source .venv/bin/activate
read -rs 'OPENAI_API_KEY?OpenAI API key: '
export OPENAI_API_KEY
```

Не отправляйте ключ в чат и не записывайте в исходники. `.env` игнорируется Git,
но автоматически не загружается. `.env.example` — только шаблон переменных.

## Сначала посмотреть план без запроса

Пример ниже использует ID модели из официальных примеров OpenAI. Замените его,
если в вашем API-проекте выбрана другая совместимая модель.

```sh
rp draft --issue 2026-10-29 --number 1 --model gpt-6-astra --output drafts/2026-10-29-api-1 --dry-run
```

`--dry-run` не требует ключа, не вызывает API и не создаёт файлов. План показывает
модель, окно поиска и лимиты. По умолчанию поиск охватывает предыдущую и текущую
дату выпуска по JST; `--since YYYY-MM-DD` меняет начальную дату.

## Получить черновик

Уберите `--dry-run`:

```sh
rp draft --issue 2026-10-29 --number 1 --model gpt-6-astra --output drafts/2026-10-29-api-1
```

Это до двух платных API-запросов: исследование с обязательным web search, затем
RU/EN/JA в строгом JSON-формате. Поиск ограничен тремя вызовами встроенных инструментов;
выход исследования — до 5000 токенов, выход редакционной стадии — до 16000.
`--max-output-tokens` меняет редакционный предел (1000–32000). Лимиты включают
reasoning tokens, поэтому слишком низкий предел может дать незавершённый ответ.
Это технические лимиты, не гарантированный денежный бюджет; стоимость зависит
от модели и инструментов. Автоматических повторов запросов нет.

Команда не публикует результат и не меняет существующий выпуск. Она создаёт:

- `drafts/.../2026-10-29.json`: проверенный по структуре выпуск со статусом draft.
- `research-response.json`: исследование с цитированиями и найденными URL.
- `editorial-response.json`: исходный структурированный ответ.
- `run.json`: стадия, лимиты, время, usage и необходимые ручные проверки.

При недостаточных данных, отказе, обрезанном ответе, сетевой или структурной ошибке
канонический выпуск не создаётся. Доступные диагностические ответы сохраняются
в каталоге черновика. Выберите новый каталог для повторной попытки; существующие
каталоги не перезаписываются. После тайм-аута результат списания может быть неизвестен.
`drafts/` исключён из Git; просмотренный источник позже переносится в `content/issues/`.

Три истории назначаются страницам 1, 2 и 3; у каждого языка те же article.id.
Редакционная стадия может использовать только URL, вернувшиеся из исследования.
Даты проверяются на формат и отсутствие будущих дат относительно выпуска.
Это не подтверждает истинность каждой новости: факты, даты первоисточников,
переводы и соответствие цитирований нужно просмотреть до утверждения.
Погода не генерируется моделью: подключайте сохранённый снимок отдельно.
Названия изданий берутся из локального шаблона, а не придумываются API.

## Локальная проверка без переноса в канонический каталог

```sh
rp validate drafts/2026-10-29-api-1/2026-10-29.json
rp build --issue 2026-10-29 --content-dir drafts/2026-10-29-api-1 --weather previews/weather-2026-10-29.json --pdf --output previews/api-review-1
rp verify --issue 2026-10-29 --output previews/api-review-1
rp preview --output previews/api-review-1
```

Аргумент `--weather` необязателен; указанный пример снимка существует в текущем
рабочем окружении. Его дата должна совпадать с датой выпуска. Отсутствие погоды
показывается явно. При переполнении сократите текст по отчёту и создайте новую сборку.

Промпты исследования и редактирования находятся в `src/replicantpravda/prompts/`.
Тесты API используют подставные ответы и не расходуют токены. Живой запрос требует
локально настроенного ключа и выбранной модели.

Официальные источники:
[Responses web search](https://developers.openai.com/api/docs/guides/tools-web-search),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## Ошибка HTTP 429

429 может означать временный лимит частоты либо недостаток квоты/кредитов.
Новая диагностика сохраняет известный error.code и числовой Retry-After, но
не сохраняет полный текст ошибки сервера: он может содержать секретные значения.
При недостатке квоты сначала проверьте API-биллинг и лимиты; повтор запроса сам
по себе эту причину не исправляет. Для повторной попытки используйте новый каталог.
Старые run.json с одним HTTP-кодом не позволяют восстановить точную причину.
См. [официальные коды ошибок](https://developers.openai.com/api/docs/guides/error-codes).
