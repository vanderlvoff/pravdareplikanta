# Импорт data/latest

Входные файлы: `ru.json`, `en.json`, `ja.json`. Для японского допускается также
`jp.json` и значение language `jp`; внутри проекта это всегда язык `ja` и маршрут
`/ja/`. Если одновременно присутствуют `ja.json` и `jp.json`, импорт останавливается.
Можно передать архивную папку, например `data/archive/2026/10/30`, вместо latest.

## Команды

```sh
rp import --input data/latest --template content/issues/2026-10-30.json --number 2 --revision 2 --output previews/imported-1/2026-10-30.json
rp validate previews/imported-1/2026-10-30.json
rp build --issue 2026-10-30 --content-dir previews/imported-1 --pdf --output previews/daily-review-1
rp verify --issue 2026-10-30 --output previews/daily-review-1
rp preview --output previews/daily-review-1
```

Число выпуска задаётся явно: входной feed его не содержит. Revision также выбирает
редактор; для нового выпуска обычно 1. Названия изданий и утверждённые изображения
не заменяются заголовком входного feed. Шаблон предоставляет названия изданий и
сохранённую погоду, только если её дата совпадает с импортируемым выпуском.
Для другой даты погоду можно отдельно передать команде build через `--weather`.

Исходные JSON не изменяются. Рядом с нормализованным выпуском создаётся
`<date>.import.json`: SHA-256 входных файлов, исходные метаданные, назначение страниц
и перечень ручных проверок. Существующий результат или отчёт не перезаписывается.
Все ошибки входных данных выявляются до записи нормализованного выпуска.
Для сборки требуется только локальный нормализованный JSON: сеть и API не нужны.

## Что сохраняется

- `title` становится `Edition.issue_title`, а `lead` — редакционным введением.
  Они видны на сайте и первой странице PDF; исходное название газеты сохраняется.
- Каждая запись `news` становится статьёй: `title` — заголовок, `body` — весь
  читательский текст. `body` обязателен: строка с абзацами через `\n` (один или
  несколько переносов); также допускается непустой массив строк-абзацев.
- `summary`, `details`, `technical_novelty`, `engineering_impact`, `limitations`,
  `evidence_status` допускаются как необязательные редакционные поля, но не
  выводятся и не используются вместо `body`. Необходимые оговорки редактор
  включает непосредственно в готовый `body`.
- В карточке новости показывается первый абзац `body`, на странице статьи и в PDF
  — весь текст. Организация и дата автоматически в текст не добавляются.
- Отсутствующий или пустой `body` останавливает импорт. Старые архивные файлы без
  этого поля требуют подготовки читательского текста перед новым импортом;
  существующие нормализованные выпуски остаются доступны без повторного импорта.
- `source_ids` разрешаются в реальные объекты источников: прямой URL, название, дата.
- `technology_signal` становится отдельной аналитической статьёй.
- Весь `glossary` становится статьёй-словарём, без пропуска терминов и определений.

Пагинация автоматическая: сначала новости, затем аналитика и словарь. Текст
последовательно заполняет две колонки каждой A4-страницы; оставшийся текст
продолжается на следующей странице. Ограничения в три страницы больше нет.
Пустое место допускается в конце последней страницы. Размер шрифта не меняется,
текст не сокращается. Старое поле print_page не задаёт фактическое размещение.

## Валидация

Поддерживаются feed schema_version `1.0` (с body), `1.2` и `1.3`, publication `pravda_replikanta`, issue_type
`daily`. Поле новости `time_window` принимает `24h`, `72h` или `7d` и не выводится. Все три языка должны иметь одинаковые issue_id, issue_date, news.id и
идентичность источников (id/URL/дата). Проверяются обязательные поля, известные
ссылки source_ids, уникальность IDs, HTTP(S)-URL, совпадение domain с URL и даты,
не выходящие за дату выпуска. Неизвестные поля отвергаются, чтобы не потерять новый
раздел незаметно. Сокращённый словарь одной из версий также вызывает ошибку.

Импорт всегда создаёт **draft**, даже если исходный lead называет события
подтверждёнными. Структурная проверка не удостоверяет факты и качество переводов;
после импорта нужны редакционный просмотр и проверка всех PNG-страниц.

## Иллюстрации v1.3

Каждая новость содержит `image`: объект для двух выбранных статей, `null` для
остальных. Объект: `url`, `path`, `type: generated`, `caption`, `alt`.
Ровно две статьи на язык иллюстрированы; IDs и файлы совпадают между языками,
а подписи и alt-текст локализованы. Импорт проверяет согласованность.

Допустимы локальные WebP из `data/images/YYYY-MM-DD/slug.webp`; URL должен быть
точным raw.githubusercontent.com/vanderlvoff/pravdareplikanta/main/ + path.
Заберите JSON и картинки через Git перед сборкой. Сборщик никогда не скачивает
изображения по URL: он копирует только явно указанные локальные файлы, без
изменения оригиналов. Отсутствующий, повреждённый, слишком большой или небезопасный
файл останавливает сборку. Внешние URL, обход каталогов и ссылки за пределы
локального data/images запрещены.

Картинка и подпись выводятся в карточке, полной статье и PDF. Пропорции
сохраняются, обрезания нет; газетный вывод монохромный. Подпись обозначает
AI-происхождение иллюстрации. В PDF рисунок с подписью переносится единым блоком.
`illustrations.json` в сборке фиксирует размеры и SHA-256 файлов; карта пагинации
фиксирует статьи, страницы и пути иллюстраций. Веб-alt не заменяется подписью.

Тестовый рисунок `tests/fixtures/editorial-illustration.webp` используется только
в тестах, не подставляется в выпуск вместо отсутствующих материалов.
