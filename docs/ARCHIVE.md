# Архив сайта

Архив предусмотрен в `PROJECT.md`, раздел 5: список выпусков, постоянные адреса
и PDF на каждом языке. Реализация описана здесь; это архив читательских страниц,
а не папка исходных feed в `data/archive/`.

## Что видит читатель

- `/ru/archive/`, `/en/archive/`, `/ja/archive/`: выпуски от новых к старым,
  сгруппированные по годам. Дата, номер, заголовок, введение, редакция и ссылка
  на чтение; последний выпуск помечен отдельно.
- `/ru/` и другие языковые главные показывают последний выбранный выпуск.
- `/ru/issues/YYYY-MM-DD/`: постоянная страница конкретного номера.
- `/ru/issues/YYYY-MM-DD/articles/<slug>/`: полная статья этого номера.
- `/ru/issues/YYYY-MM-DD/edition.pdf`: его PDF, если сборка выполнена с `--pdf`.

Для EN/JA структура такая же. Переключение языка сохраняет архив, выбранный номер
или статью. Возврат из статьи ведёт к ней в её выпуске. Одинаковые slug разных
выпусков, включая глоссарий, не конфликтуют. Старые адреса `/ru/articles/<slug>/`
сохранены как совместимые страницы; при повторении slug они показывают наиболее
новый из включённых вариантов. Для постоянных ссылок используйте адрес с датой.

## Собрать текущий архив локально

Из корня репозитория, в активированной `.venv`:

```sh
rp build --issue 2026-10-31 --content-dir content/technical \
  --archive-issue content/technical/2026-10-30.json \
  --pdf --output previews/archive-2026-10-31-8
rp verify --issue 2026-10-31 --output previews/archive-2026-10-31-8
rp preview --output previews/archive-2026-10-31-8
```

Откройте http://127.0.0.1:8000/ru/archive/. Для английского и японского замените
`ru` на `en` или `ja`. Существующая сборка не перезаписывается: для повторной
сборки выберите другой `--output`. Уберите `--pdf` для быстрой веб-сборки —
ссылок на отсутствующие PDF не будет.

`--archive-issue JSON` можно повторять для каждого предыдущего выпуска. Указывайте
нормализованные файлы формата `Issue`, не отдельные ru/en/ja feed. Новые feed
сначала импортируются по [DAILY_IMPORT.md](DAILY_IMPORT.md). У одного номера
в сборке может быть только одна редакция; повтор даты вызывает ошибку.
Архивный выпуск не может быть новее выбранного главного. `issue_id` должен
совпадать с `publication_date`.

Сборщик ничего не ищет рекурсивно в `content/` или `data/archive/`. Это намеренно:
там есть альтернативные редакции и демонстрационный вымышленный выпуск за
29 октября. В текущий архив включены только явно выбранные 30 и 31 октября.
Без `--archive-issue` архив содержит один текущий номер.

## История и воспроизводимость

Каждый номер использует свой текст, подписи, иллюстрации и сохранённую погоду.
Флаги `--weather` / `--edition-weather` относятся только к текущему номеру;
для истории прогноз берётся из её JSON. Никаких сетевых запросов при сборке нет.

Сборка хранит `archive.json` с перечнем дат/редакций, `sources/<date>.json` для
каждого номера и `source.json` для последнего. Все HTML, локальные изображения
и PDF входят в `artifacts.json`. Проверка охватывает внутренние ссылки, якоря,
контрольные суммы и PDF всех включённых номеров. Ошибка в историческом номере
тоже отменяет сборку целиком. Успешные предыдущие снимки сохраняются.

Это воспроизведение выбранной редакции в текущих шаблонах. Для сохранения точного
старого оформления и исходных байтов иллюстраций храните неизменяемые сборки:
пересборка использует текущие шаблоны и текущие локальные файлы `data/images/`.
Другие редакции исходников остаются в Git и не появляются отдельными номерами.

## Статус публикации

Обычный build — локальный просмотр, включая явно выбранные `draft`/`review`, с
`noindex,nofollow`, запрещающим robots.txt и отключённой публикацией. Автоматический
сбор всех черновиков не добавлен. Полные новые выпуски после генерации/импорта
получают approved автоматически. Окончательное редакционное подтверждение
выполняется на шаге загрузки в Cloudflare; approved не запускает публикацию.
RSS и поисковые метаданные описаны в [DISCOVERY.md](DISCOVERY.md). Поиск по архиву
и публикация пока не реализованы.

Для GitHub/Cloudflare используйте отдельный --publication и rp release: исходные
JSON и диагностические снимки в public/ не включаются. См. [DEPLOYMENT.md](DEPLOYMENT.md).
